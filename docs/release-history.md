# Public Release History

This is the short public-facing history of Contextrail.

It compresses the detailed maintainer changelog into the major shifts
that shaped the template from the public-launch `0.8.x` line back to
its early bootstrap releases.

## [0.8.0] — 2026-05-07

Contextrail enters its public-launch line.

- The template is now explicitly scoped to the **engine/language layer**:
  hex modules, agent contract adapters, commit ceremony, claim
  coordination, context briefing, and delivery guardrails.
- Operator-facing dispatch tooling has been extracted behind the
  open-core boundary into a separate product track that will launch on
  its own roadmap.
- The public documentation now describes the template in its `v0.8.0`
  shape: current validation scope, known release boundaries, and the
  manual BYO-LLM workflow preserved for non-product users.
- The public baseline reflects **39 core modules plus 1 teaching
  example**, with structural measurements reproducible from the shipped
  repository.

## [0.7.x] — parallel-session hardening

The focus shifted to safe parallel agent work:

- worktree lifecycle as a first-class delivery model
- stronger claim enforcement on shared surfaces
- stricter commit ceremony and version discipline
- better isolation against cross-session drift

This line made the "many agents, one repo" claim operational rather than
purely structural.

## [0.6.x] — launch-readiness and measurement

The repository hardened into a publishable architecture template:

- stronger deterministic quality gates
- seam / Branch by Abstraction operational maturity
- framework-in-hex guidance and migration docs
- structural measurements for context efficiency and bounded delivery
- public positioning of COA as architectural guardrails for AI agents

This is the line where Contextrail's current public architectural story
became coherent and measurable.

## [0.5.x] — capability breadth and template coverage

The template expanded its functional surface with new modules for
multi-tenant, PWA, SEO, GraphQL, theming, prerendering, and related
application concerns.

This line closed much of the gap between a small architecture demo and a
real reusable application template.

## [0.4.x] — sidecar-first metadata

The repository moved from heavy inline headers to slim inline headers
plus sparse sidecars.

That change reduced file-level context noise and made the repo much more
navigable for agents working through bounded metadata instead of
deep-reading source by default.

## [0.3.x] — product-data, coordination, and infrastructure expansion

The repository grew from a small starter into a broader application
template:

- richer product-data and persona workflows
- claims-based inter-agent coordination
- server-side adapter packs and an API starter
- a much larger set of infrastructure-oriented hex modules

This was the line where Contextrail started to behave like a serious
multi-surface template rather than a narrow starter app.

## [0.2.x] — documentation and COA articulation

The project gained its first broad documentation surface: getting
started, module catalog, technical reference, FAQ, and the first
whitepaper.

This line also introduced the early Context-Optimized Architecture
(COA) framing: the system map, dependency graph, manifest-driven
navigation, and tiered context loading for bounded agent work.

## [0.1.x] — bootstrap

The template began as a lean modular-monolith starter with the first
hexagonal module boundaries, deterministic scripts, and a repository
shape designed to stay runnable without a heavy build stack.

## What To Expect Next

- The `0.8.x` line is for public hardening, documentation cleanup, and
  follow-up fixes ahead of `1.0`.
- `1.0` follows the Publication Readiness Audit pass. There is no
  committed timeline yet.
