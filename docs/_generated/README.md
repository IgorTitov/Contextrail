# docs/\_generated

Machine-generated artifacts that exist so agents and humans can answer
high-leverage questions from a single file read instead of grepping the
whole repository. Nothing in this folder is hand-edited — every file
here is the deterministic output of a `scripts/checks/*.mjs` generator,
and the pre-commit `test-gate` blocks commits that drift from regenerated output.

## What lives here

| File | What it answers | Generator | Drift check |
|------|-----------------|-----------|-------------|
| `dependency-graph.json` | Forward deps, reverse deps, consumer edges ("who imports `modules/<X>/public-api.mjs`?"), topological layers, and safe removal order for all 38 modules. | `scripts/checks/dependency-graph.mjs` | `node scripts/checks/dependency-graph.mjs --check` |
| `spec-index.json` | The flattened, ID-indexed view of every PRD / USM / backlog work item, used by `spec-check` and `pre-impl-gate` to resolve `SpecRefs:` references. | `scripts/checks/spec-sync.mjs` | `node scripts/checks/spec-check.mjs` |

Tier-2 capability surface (machine-readable port shapes, supporting typedefs, and adapter inventories) lives in each `modules/<name>/manifest.json` under the top-level `capabilities` block, generated by `scripts/checks/capabilities-sync.mjs` (ADR-0010).

## How to regenerate

```bash
node scripts/checks/dependency-graph.mjs              # rewrite dependency-graph.json
node scripts/checks/spec-sync.mjs                     # rewrite spec-index.json
```

Both generators are idempotent and emit a stable JSON serialization
(`dependency-graph.json` ignores the `_generated` timestamp under `--check`).

## How agents should use these files

- **Hex-architect / feature-implementer**: read `dependency-graph.json`
  before refactoring or removing a `public-api.mjs` export. The
  `consumers` array on each module is the complete blast radius.
- **Spec-aware tooling**: read `spec-index.json` to resolve any
  `TPL-xxx` reference to its work-item record (status, type, parent,
  acceptance, prd/usm refs) without parsing the backlog markdown.
- **Don't hand-edit** — any change here will be overwritten on the
  next generator run, and the `--check` mode will block the commit.

## Why this folder exists

The COA brand promise is that an agent can orient on the repository
from a ~2.5K-token cold read (tier 1 + tier 2 with capability surface). Generated artifacts collapse expensive
multi-file scans (grep imports across 38 modules; walk three doc trees
for backlog status) into a single deterministic JSON file the agent
can read once and reason against. Adding a new artifact here is
appropriate when the answer is repeatedly needed, mechanically
derivable, and would otherwise force every agent to redo the same scan.
